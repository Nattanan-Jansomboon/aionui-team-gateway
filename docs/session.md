# Session ของ AionUi: ต่ออายุเองอย่างไร และเมื่อไหร่ต้อง pair ใหม่

AionUi ไม่มี username/password การ pair ต้องมีคนกดอนุมัติบนเดสก์ท็อป gateway จึงล็อกอินเองไม่ได้ สิ่งที่ทำได้คือเก็บ session ที่ pair แล้วไว้ และ **ต่ออายุให้เองก่อนหมด** เอกสารนี้อธิบายว่าระบบทำอะไรให้เอง และคุณต้องทำอะไรเอง

## ข้อมูลที่เก็บ

เก็บใน `session_state.json` ที่รากโปรเจกต์ (ไม่ขึ้น Git) โดย `src/session_store.py` เป็นคนจัดการ

| ค่า | หน้าที่ | อายุ |
|---|---|---|
| `aionui-session` | JWT ของ session ใช้กับทุก API | ราว 30 วันนับจากครั้งที่ออกล่าสุด |
| `aionui-refresh` (refresh token) | ใช้แลกโทเค็นชุดใหม่ที่ `/api/auth/refresh` เท่านั้น | ราว 30 วันนับจากครั้งที่ออกล่าสุด |
| `aionui-csrf-token` | ส่งเป็น header `x-csrf-token` กับคำขอที่เปลี่ยนข้อมูล | ตามรอบ session |
| `aionui-webhost-session` | cookie ของ web-host ตอน pair | 30 วันนับจากวัน pair (ดู "ข้อจำกัด") |

## ระบบทำอะไรให้เอง

gateway ต่ออายุ session ด้วย `POST /api/auth/refresh` (วิธีเดียวกับที่หน้าเว็บของ AionUi ทำเมื่อเจอ 401) ใน 3 กรณี

1. **ก่อนหมด:** ลูป keepalive ทุก `AION_PING_MINUTES` นาที (ค่าตั้งต้น 10) ถ้าโทเค็นเหลือน้อยกว่า `AION_REFRESH_MARGIN_HOURS` (ค่าตั้งต้น 24 ชั่วโมง) จะต่ออายุ
2. **เจอ 401 หรือ 403:** ตอนส่งข้อความ อ่านประวัติแชต หรือเช็ก session จะต่ออายุแล้วส่งคำขอเดิมซ้ำหนึ่งครั้ง
3. **WebSocket ถูกปฏิเสธตอน handshake:** ต่ออายุแล้วต่อใหม่หนึ่งครั้ง

ลำดับการต่ออายุหนึ่งรอบ

```
ขอ lock ไฟล์ (session_state.json.lock) ──► โหลดไฟล์ใหม่ ──► ถ้ามีโปรเซสอื่นต่อไปแล้ว: ข้าม
   ──► POST /api/auth/refresh (ส่ง refresh token ทั้งใน cookie และ body)
   ──► เก็บ token + refresh_token ใหม่จาก body และ CSRF ใหม่จาก Set-Cookie ลงไฟล์
   ──► ปล่อย lock ──► ส่งคำขอเดิมซ้ำด้วยค่าใหม่
```

- gateway และ MCP server ใช้ไฟล์เดียวกัน มี lock กันต่ออายุชนกัน (เพราะ refresh token อาจถูกเปลี่ยนทุกครั้ง)
- ไฟล์ถูกโหลดใหม่ทุกคำขอเมื่อมีการแก้ ทั้งสองโปรแกรมจึงใช้ค่าล่าสุดทันที ไม่ต้องรีสตาร์ท
- ทุกครั้งที่ต่อสำเร็จ จะได้โทเค็นอายุ 30 วันใหม่ ตราบที่ gateway ทำงานอยู่ (หรือถูกเรียกใช้อย่างน้อยทุก 30 วัน) จึงไม่หมดอายุ

## เมื่อต้อง pair ใหม่ (ทำเอง ไม่ถึงนาที)

ต้องทำเมื่อ refresh token หมดอายุ (เช่น gateway ดับเกิน 30 วัน) หรือ `/session/status` ขึ้น `ok: false`

1. เปิด WebUI ในเบราว์เซอร์ แล้ว pair ใหม่ (pairing code และกดอนุมัติบนเดสก์ท็อป)
2. เอา refresh token, Cookie และ CSRF มาใส่ตามขั้นตอนใน [setup.md](setup.md#ใส่-session-ครั้งแรก)
3. รัน `python scripts/update_session.py` (ไม่ต้องรีสตาร์ท gateway หรือ MCP)

## ตรวจสถานะ

```bash
python scripts/update_session.py --status
```

แสดงว่ามี cookie อะไรบ้าง มี refresh token หรือไม่ เวลาต่ออายุสำเร็จล่าสุด และเวลาที่เหลือ (ไม่แสดงค่าลับ) หรือเปิด `http://127.0.0.1:8000/session/status` เพื่อดูว่า session ใช้ได้ไหมตอนนี้ (`ok: true/false` พร้อมเหตุผล) และดูข้อความที่ขึ้นต้นด้วย `[session]` ใน terminal ที่รัน `uvicorn`

## ข้อจำกัดและสิ่งที่ยังไม่ยืนยัน

ยืนยันกับ AionUi จริงแล้ว: เรียก refresh จาก gateway ได้ 200 ได้โทเค็นใหม่อายุ 30 วัน และเรียก API ต่อได้

ยังไม่ยืนยัน (อาจกระทบการใช้งานระยะยาว)

- **เพดาน 30 วันของ `aionui-webhost-session`** ตามโค้ดของ AionUi cookie นี้มีอายุคงที่นับจากวัน pair และ refresh ไม่ยืดให้ ยังไม่ทราบว่าถ้าหมดแล้ว API ที่เรียกผ่านพอร์ต WebUI จะถูกปฏิเสธจริงหรือไม่ ถ้าใช่ ต้อง pair ใหม่ทุกประมาณ 30 วัน (ยังไม่มีการเตือนล่วงหน้าเรื่องนี้)
- **การต่ออายุตอนที่ session หมดไปแล้วจริง** ที่ทดสอบคือตอนยังไม่หมด
- **refresh token ถูกเปลี่ยนทุกครั้งแล้วใบเก่าใช้ไม่ได้หรือไม่** ถ้าใช่และคุณเปิด WebUI ในเบราว์เซอร์ด้วย session ชุดเดียวกัน เบราว์เซอร์กับ gateway อาจทำให้ชุดของกันและกันใช้ไม่ได้ (lock กันได้เฉพาะ gateway กับ MCP)
- **CSRF ใหม่** response ของ refresh ที่เห็นไม่มี `Set-Cookie` ถ้า CSRF ไม่เปลี่ยน ค่าเดิมก็ใช้ต่อได้

## ความปลอดภัย

- `session_state.json` เทียบเท่ารหัสผ่านของ AionUi ห้าม commit ขึ้น Git (`.gitignore` กันไว้แล้ว) และอย่าส่งให้ใคร
- ถ้าเริ่ม gateway ด้วยค่า `AION_SESSION_COOKIE` หรือ `AION_CSRF_TOKEN` ชุดใหม่ ระบบถือว่าคุณตั้งใจเปลี่ยน และใช้ค่านั้นแทนค่าในไฟล์ (แต่แนะนำให้ใช้ `update_session.py` แทน)
- ไม่เก็บ cookie วิเคราะห์การใช้งาน (`rl_*`, `ph_*`) ลงไฟล์
